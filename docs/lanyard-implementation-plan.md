# 경력 카드 초기 화면

## 확정한 UX

첫 화면은 아하랩스, 티맥스 클라우드, 개인 프로젝트 세 카드다. 캐러셀은 사용하지 않는다. 회사 카드 앞면에는 회사명, Frontend 연구원, 재직 기간을 표시한다. 개인 카드는 제목과 작업 성격만 표시하고 확인되지 않은 날짜는 만들지 않는다.

카드를 100px 이상 아래로 당긴 뒤 놓으면 같은 페이지에서 선택한 카드와 상세를 표시한다. 짧게 당기면 복귀한다. 112px까지 이동을 제한한다. pointercancel, capture loss, Escape, 창 blur, 화면 이탈은 상세 진입 없이 취소한다. 카드 자체의 클릭/Enter로도 같은 상세를 연다. 상세 제목으로 포커스를 옮기고, “경력으로 돌아가기”는 선택했던 카드로 포커스를 복귀시킨다.

## 공통 컴포넌트 계약

`Lanyard`는 `title`, `role`, 선택적 `period`, 선택적 `design`, `href`, `onOpen`, `id`를 받는다. 상세 데이터는 카드와 분리한다.

`design`은 줄 바탕색/테두리색/반복 레이블과 간격, 카드 바탕색/배경 이미지/외곽선/글자색/하단 두 색과 비율을 받는다. 이미지와 텍스트를 분리해 배경만 교체할 수 있다. 입력하지 않은 줄 테두리는 줄 바탕색으로 채우고, 카드 외곽선은 투명하게 둔다. 카드 전체 디자인을 생략해도 기본 디자인을 표시한다.

모든 카드 크기는 224×304px, 줄 너비는 24px, 양쪽 테두리는 각각 2px이다. 데스크톱과 모바일, 선택한 카드 상세에서도 공통 크기를 유지하며 카드별 크기 옵션은 제공하지 않는다. 좁은 화면에서는 세 카드를 세로로 배치하고 카드 바깥 영역으로 스크롤한다.

티맥스는 제공된 사진을 참고해 흰 바탕, 하단 빨강(#bd2839) 70%와 파랑(#183b80) 30%, 파란 줄과 빨간 테두리를 적용한다. 사진 자체를 게시하거나 인물 사진을 추출하지 않는다. 아하랩스는 검정 줄에 `#e60027` 테두리를 적용하고, 개인 카드는 기본 디자인을 사용한다.

## 구현 구조

- `data/portfolio.ts`: 경력, 개인 작업, 관련 Case Study ID와 디자인
- `hero/badge-design.ts`: 디자인 타입, 기본값, 공통 치수
- `hero/StaticBadgeFallback.tsx`: 모든 환경에서 동일하게 사용하는 HTML 카드 앞면
- `hero/Lanyard.tsx`: 카드별 포인터 상태, 정적 줄, DOM 카드 이동과 상세 진입
- `hero/LanyardShelf.tsx`: 선반 측정, 환경 판단, 지연 로딩, 공유 Canvas와 실패 처리
- `hero/LanyardScene.tsx`: 하나의 R3F/Rapier 월드 안에서 세 줄과 카드의 물리 계산 및 DOM 위치 동기화
- `hero/Hero.tsx`: 세 카드 선택과 상세 전환, 포커스 복귀

텍스트는 Canvas에 굽지 않고 DOM으로 유지한다. 데스크톱 960px 이상, fine pointer, 모션 감소 미사용 시에만 3D를 import한다. 세 카드는 선반 전체를 덮는 Canvas와 Physics 월드 하나를 공유하고, 충돌하지 않는 독립된 줄로 계산한다. DPR 상한 1.5, 물리 timestep 1/60, 뷰포트 이탈/백그라운드에서는 물리 및 렌더링을 멈춘다.

줄은 Catmull–Rom 곡선을 재사용하고 두 개의 고정 버퍼 리본으로 그린다. 매 프레임 벡터/배열 생성이나 React state 갱신이 없고, 2px 줄 테두리를 유지한다. 정적 카드도 포인터 당기기와 접근 가능한 링크를 제공한다. WebGL 실패/컨텍스트 유실/15초 로딩 실패 시 정적 동작으로 전환한다.

## 검증

Astro check, Vitest, production build 및 Playwright에서 크기·배색, 키보드 및 포커스, 임계값, 취소, reduced-motion, WebGL 실패, JavaScript 없는 링크, 물리 복귀 및 기존 프로젝트 탐색을 검증한다. 브라우저 검수는 데스크톱/모바일에서 시행한다.

## 체크포인트 — 3D 로딩 및 실행 비용

상태: 구현 및 자동 검증 완료, 사용자 확인 대기.

- 최적화 전 물리 청크는 원본 3,157,285바이트, 로컬 gzip 측정 1,077,143바이트였다.
- 최적화 전에는 데스크톱 첫 화면에서 물리 청크를 즉시 요청하고 카드마다 Canvas와 물리 월드를 하나씩 만들었다.
- 최적화 후에는 카드에 포인터가 진입하거나 키보드 포커스가 이동하기 전까지 물리 청크를 요청하지 않는다.
- 첫 사용 의도 뒤 선반의 공유 물리 장면을 활성화하고, 세 카드를 오가더라도 같은 Canvas를 유지한다.
- 정적 카드의 당기기·클릭·키보드 동작을 그대로 유지하므로 물리 코드가 로드되는 동안에도 상세를 열 수 있다.
- 물리 청크 자체의 크기는 그대로다. Rapier 기반 제약과 흔들림을 유지하는 대신 초기 경로에서 제외하는 선택이다.
- `npm run verify`: Astro 오류 0건, Vitest 7개 통과, 정적 페이지 10개 빌드 완료.
- `npm run test:e2e`: 29개 통과, 모바일에서 해당하지 않는 데스크톱 물리 전용 3개 제외.

다음 시작점: 사용자 확인 후 카드 사용감에 영향을 주는 수치 조정이 필요한지 판단한다. 물리 청크 자체를 줄이려면 Rapier를 작은 2D 제약 솔버로 교체해야 하므로 별도 설계 마일스톤으로 취급한다.

## 체크포인트 — 카드 내부 드래그 안내

상태: 구현 및 자동 검증 완료. 사용자 확인 대기.

- 안내 문구 영역의 높이와 여백을 드래그 시작 때 펼쳐, 카드 하단에서 들어오며 직급·기간 블록을 위로 밀어 올리게 한다. 레이아웃 변경은 pointer move가 아니라 드래그 상태 전환 때만 발생한다.
- 포인터를 누르면 `아래로 당겨서 열기`, 100px 임계점을 넘으면 `놓아서 상세 보기`를 transition으로 교차 노출한다.
- 놓기, pointer cancel, Escape 및 기존 전역 취소 경로에서 안내를 다시 숨긴다.
- 시각 문구와 별도의 live region으로 현재 드래그 상태를 보조 기술에 전달한다.
- 카드별 Canvas 활성 상태가 바뀌어 부모가 다시 렌더되더라도 입력이 같은 카드 면은 `memo`로 재사용한다. 안내 문구는 13px 중앙 정렬로 표시한다.
- 카드 자체가 클릭, 키보드 Enter, 드래그를 모두 담당하므로 Canvas 하단의 중복 경력 보기 링크는 제거한다.

검증 결과:

- `npm run check`: Astro 진단 0건
- `npm run test`: Vitest 7개 통과
- `npm run test:e2e -- e2e/lanyard.spec.ts --workers=1`: 데스크톱·모바일 21개 통과, 모바일 비대상 3D 검사 3개 제외
- 밀어내기 전환 집중 검사: 데스크톱·모바일 2개 통과

## 체크포인트 — 공유 Canvas와 Physics 월드

- `ResizeObserver`로 선반과 각 열의 중심을 측정해 세 줄의 고정점을 하나의 좌표계에 배치한다.

## 체크포인트 — 줄 인쇄 패턴을 리본 재질에 통합

상태: 구현 및 자동·화면 검증 완료. 사용자 확인 대기.

- 투명 CanvasTexture 글자 메시를 제거하고 검정 바탕과 흰 `AHHA Labs` 문구를 담은 SVG를 내부 리본 재질에 직접 매핑한다.
- 빨간 외부 리본은 유지한다. 줄 geometry는 카드당 두 겹이며, 정적 DOM 줄도 같은 SVG를 반복 배경으로 사용한다.
- 디자인 입력은 `strapPattern: { src, repeatLength }`로 변경했다. 아하랩스 패턴은 문구 길이 60px와 빈 공간 48px를 합친 108px 주기이며 글자 크기는 12px다.
- 곡선의 누적 길이로 UV를 계산해 굴곡마다 글자와 간격이 불균일하게 늘어나는 것을 줄인다.
- 파비콘과 카드 로고 장식은 사용자가 새 로고를 제공할 때까지 범위에서 제외한다.
